Executive Summary

Wealth Stewards will have every new client record from its back-office platform arrive in its CRM automatically each day, with no manual uploads, through a scheduled load that can be live within two weeks. Three things make this the right next step. First, it removes a daily manual handoff, so advisors work from current client data instead of waiting on a file to be keyed in. Second, nothing fails silently: every rejected record is captured with the reason it was rejected and set aside for review, so the team can correct and reload it with confidence. Third, it fits the firm's infrastructure and security posture, with three deployment paths to choose from, including one that keeps integration credentials entirely off any externally facing server. The result is a dependable daily data flow, delivered as a fixed, focused engagement that Wealth Stewards can build on as its integration needs grow.
2.0

Project Charter

NDEX delivers a daily CSV export of new client records to an FTP server. This engagement automates loading those records into Salesforce as Account records, on a schedule, with every file routed and every failure reported.

Integrate 2 Cloud offers three ways to deploy the integration, and Wealth Stewards selects one. Option 1 runs Data Loader on a separate, dedicated machine and leaves the FTP server untouched. Option 2 runs Data Loader directly on the FTP server, which Wealth Stewards prepares to I2C's specification. Option 3 has I2C set up the SFTP server itself and then deploy Data Loader on it. All three deliver the same daily load, file routing, error handling and run logging. Toggle the option in the Investment section to see its scope, timeline and price.

Strategic Objectives

Load new client records from the daily NDEX CSV export into Salesforce as Account records without manual effort
Run the load automatically once per day on a scheduled task
Route every source file to a Processed or Error folder so the state of each day's file is always clear
Capture every rejected record with Salesforce's reason so it can be corrected and reloaded

Expected Outcomes

New NDEX clients appear in Salesforce the day they are exported, giving advisors current data without a manual upload step
Failed records are never lost: each one is listed with its rejection reason and moved to the Error folder for review
A daily run log gives Wealth Stewards a simple audit trail of what was loaded and when
A deployment path matched to the firm's server platform and security requirements

5.0 Roles & Responsibilities

5.1 Client Responsibilities

IT / Infrastructure Lead
  • Provide the machine that will run Data Loader (Option 1 dedicated machine, Option 2 prepared FTP server, or Option 3 Windows host)
  • Provide a user with administrator access to install and configure Data Loader and the scheduled task
  • Ensure outbound HTTPS (port 443) from that machine to Salesforce
  • Provide FTP server access and network access needed for the file transfer method (Option 1)
Salesforce Administrator
  • Create a dedicated Salesforce integration user with permission to create Account records
  • Confirm the Account fields each NDEX column should populate
  • Review the test load results and sign off

Foundational Assumptions
General
  • Wealth Stewards selects one of the three options before work begins
  • No discovery or project governance is required; requirements are as described in this SOW
  • All work is performed remotely, with access provided within 2 business days of kickoff
Technical
  • NDEX delivers one CSV file per day to the FTP server in a consistent column layout
  • The load creates new Account records. If existing Accounts must also be updated (upsert), this is confirmed before build and may adjust hours
  • Options 2 and 3 require a Windows or macOS server. If the FTP server runs Linux, Option 1 is recommended
  • Under Option 3, Wealth Stewards provides the Windows host (physical, virtual or cloud) and any firewall or DNS changes; I2C installs and configures the SFTP service on it
  • The Salesforce integration user's credentials are stored encrypted on the machine running Data Loader
